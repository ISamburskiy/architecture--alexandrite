**Мотивация**
Работы по реализация мониторинга ведутся с целью контроля над работоспосоностью системы с учетом повышающейся нагрузки. 
Мониторинг позволит:
- выявлять узкие места в бизнес-процессах для повышения скорости внутренних процессов;
- спланировать масштабирование системы для устранения рисков простоев и сбоев;
- спланировать доработки по общей отказоустойчивости системы.

**Подход к мониторингу**
Для мониторинга можно ориентироваться на подход четырех золотых сигналов. 
Для API магазина (и API MES, которым польщуются внешние продавцы) акцент будет на "задержке". Для MES-сервиса и очереди сообщений на насышенности.

**Метрики**
Для API магазина и API MES для внешних продавцов анализируем RPS, RPS per User (этот показатель - как часть мониторинга безопасности) и Latency.
Для основных внутренних сервисов и баз данных анализируем CPU и Memory Utilization для планирования масштабирования.
Также анализируем длину очередей для Rabbit MQ

**План действий**
1. Добавляем в деплои сервис Prometheus
2. Постепенно дорабатываем каждый из сервисов для подключения к сбору метрик. Предпочтительный порядок:
   - MES API
   - MES db
   - Shop API
   - Shop DB
   - Messages Queue
   - CRM API
   - 3d files storage
4. При необходимости более сложной визуализации развертываем Grafana.

**Анализ насыщенности**
На текущем этапе насыщенность в первую очередь определяем по CPU и Memory Utilization MES API и MES DB, а также по длине очереди Rabbit MQ как предположительных узких местах системы.
